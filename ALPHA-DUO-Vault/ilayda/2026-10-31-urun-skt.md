# 2026-10-31 — Ürün raf ömrü, SKT ve yeni lot/stok girişi

## Kök neden
- `products`/`materials` tablolarında `created_at` ve `shelf_life_days` yoktu.
- Stok girişi ekranı yalnızca **mevcut lotları** listeliyordu. Yeni eklenen
  ürünün lotu olmadığı için seçilemiyor, stok girişi yapılamıyordu.
- SKT tamamen istemcinin gönderdiği `expiry_date` değerine bağlıydı; üretim
  tarihinden otomatik hesaplanmıyordu.

## Yapılanlar
### Backend
- `products` ve `materials`:
  - `shelf_life_days INT NOT NULL DEFAULT 0`
  - `created_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP`
- `POST /products` ve `POST /materials` bu alanları kabul ediyor; cevapta
  `created_at` dönüyor.
- `CreateLot` tek transaction:
  - ürün/hammadde raf ömrünü okur,
  - `received_at` (üretim/alış) + raf ömrü = `expiry_date`,
  - `qty > 0` ise `inbound` stok hareketi yazar,
  - lot bakiyesini aynı transaction’da günceller.
- Üretim emri çıktı lotları ve butchery’nin oluşturduğu ürün lotları da
  üretim/parti tarihi + ürün raf ömrü ile SKT alır.
- `ErrInvalidLot` → HTTP 400.

### Web
- `Inventory` ekranı:
  - “Ürün ekle” formu (kod, ad, birim, satış fiyatı, kategori, raf ömrü),
  - hammadde formuna raf ömrü,
  - “Yeni lot + stok girişi” formu: ürün/hammadde seçimi, üretim tarihi,
    miktar, maliyet; SKT backend’de hesaplanır,
  - ürün kartları tablosunda raf ömrü + eklenme tarihi,
  - lotlar tablosunda tip, üretim/alış tarihi ve SKT.
- Mevcut lota stok hareketi formu korundu; artık tüm lotları listeler.
